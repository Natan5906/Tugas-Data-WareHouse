Dokumen ini disusun berdasarkan eksekusi notebook dan pemeriksaan database hasil ETL.

1. Ringkasan Eksekutif

Proyek ini mengimplementasikan pipeline Extract, Transform, Load (ETL) untuk memuat data pengukuran sensor IoT ke dalam data warehouse berbasis SQLite. Data berhasil diekstrak dari CSV, divalidasi, dibersihkan, ditransformasi, dimuat ke star schema, dan dianalisis menggunakan query SQL.

Kesimpulan utama: pipeline berhasil dijalankan dari awal sampai akhir tanpa error, database berisi 14.400 fact records, dan skor kualitas data tercatat 100%.

2. Tujuan Implementasi

  • Membangun pipeline ETL yang terstruktur dan dapat dijalankan ulang.
  • Membersihkan dan memvalidasi data sensor sebelum dimuat ke warehouse.
  • Merancang star schema untuk kebutuhan analitik.
  • Menyediakan query analitik untuk memperoleh insight kualitas udara.
  • Memverifikasi integritas data dan jumlah record hasil pemuatan.

4. Proses ETL

4.1 Extract

Data dibaca menggunakan Pandas dari file CSV sumber. Struktur kolom dan jumlah baris diperiksa sebelum transformasi.

4.2 Transform

  • Timestamp dikonversi ke tipe datetime.
  • Nama lokasi distandardisasi.
  • Baris duplikat dihapus dengan mempertahankan kemunculan pertama.
  • Nilai numerik diperiksa terhadap batas kewajaran.
  • Nilai di luar rentang ditangani dengan clipping sesuai aturan kualitas data.
  • Nilai numerik yang kosong diisi menggunakan median kolom.
Setelah standardisasi nama lokasi, transformasi mengidentifikasi 14.414 baris sebagai duplikat. Hal ini konsisten dengan pola data sumber yang memuat pembacaan sensor berulang. Setelah pembersihan, tersisa 14.400 record unik untuk fact table.

4.3 Load

Data dimuat ke SQLite menggunakan batch processing dan relasi foreign key. Proses bersifat idempoten terhadap database yang sudah berisi data; pada eksekusi validasi terakhir, data telah tersedia sehingga tidak dimuat ulang.

5. Rancangan Data Warehouse

Warehouse menggunakan pendekatan star schema dengan satu fact table dan tiga dimension tables.

Hasil tersebut diperoleh dari agregasi rata-rata AQI, jumlah pembacaan per lokasi dan periode waktu, serta perbandingan aktivitas sensor. Karena semua sensor memiliki jumlah pembacaan yang sama, hasil query yang menampilkan SENSOR_001 merupakan tie-break, bukan keunggulan jumlah pembacaan.

8. Kendala dan Perbaikan

  • Ditemukan karakter asing pada kode data_loader.py yang menimbulkan IndentationError. Karakter tersebut dihapus dan file berhasil lolos pemeriksaan sintaks.
  • Ringkasan notebook sebelumnya menyebut seluruh record sebagai “loaded”, padahal database sudah berisi data. Ringkasan diperbaiki menjadi “records in warehouse” dan “loaded this run” agar interpretasinya akurat.
  • Tampilan struktur proyek dibatasi agar tidak mencetak seluruh isi virtual environment.

9. Kesimpulan dan Rekomendasi

Implementasi data warehouse sensor IoT telah selesai dan memenuhi tujuan utama. Pipeline dapat membaca data, melakukan transformasi, memuat star schema, menjalankan analitik, dan menghasilkan metrik kualitas yang dapat diverifikasi.

Rekomendasi pengembangan berikutnya:

  • Menambahkan scheduler seperti Apache Airflow untuk otomatisasi ETL.
  • Membangun dashboard monitoring AQI dan kondisi sensor.
  • Menambahkan alert untuk anomali dan penurunan kualitas data.
  • Mengembangkan forecasting AQI dan deteksi anomali.
  • Menerapkan kontrol akses, dokumentasi lineage, dan governance data.
